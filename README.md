# MCMit
Mid-circuit Measurement Error Mitigation

## Repository structure

| Path | What it is |
|---|---|
| `applications/` | The paper's benchmark circuits: constant-depth GHZ, long-range CNOT, teleportation, qubit reuse |
| `backends/` | QPU/simulator backend definitions and calibration data |
| `compiler/branching/` | Stochastic branching (§7.3) |
| `compiler/decoding/` | Measurement hardening — parity checks, repetition codes (§7.2) |
| [`compiler/removal/`](compiler/removal/README.md) | Static MCM elimination (§7.1), forked from [pcm-ccop-dc-pass](https://github.com/i2-tum/pcm-ccop-dc-pass) |
| [`qubit_state_discrimination/`](qubit_state_discrimination/README.md) | MCMit-CNN / MCMit-T discriminators and the HERQULES/QubiCML/baseline comparisons (§6, §8.3) |
| [`branch_instruction/`](branch_instruction/README.md) | The FPGA controller for `branch_reduce_fproc` (§5), forked from [QubiC](https://gitlab.com/LBL-QubiC) |
| [`lattice-sim/`](lattice-sim/README.md) | The QEC simulator behind Fig. 3 and Fig. 13 (§3.3, §8.5) — see [reproduction steps below](#reproducing-the-qec-results-surface-code--33-and--85) |
| `evaluation/` | Per-benchmark evaluation scripts, plus [`evaluation/motivation/MECH/`](evaluation/motivation/MECH/README.md) for Fig. 2 (§3.2) |
| [`results/`](results/README.md) | Every figure's CSV data, in one place |
| `plotting/` | The remaining top-level plotting scripts (Fig. 10, 11, 12) |

## Dependencies

MCMit's own code (`applications/`, `backends/`, `compiler/`, `evaluation/`,
`plotting/`) needs:

- **Qiskit** (`qiskit`, `qiskit-aer`, `qiskit-ibm-runtime`) — circuits, simulation, hardware access
- **mthree** — Qiskit M3 readout calibration, used by stochastic branching and GHZ evaluation
- **NumPy**, **pandas**, **NetworkX**, **matplotlib**, **seaborn** — numerics, the DAG compiler pass, plotting

Pinned in [`requirements.txt`](requirements.txt): `pip install -r requirements.txt`.

Each vendored subproject pins its own dependencies separately, since they're
independent tools with their own environments:
[`lattice-sim/requirements.txt`](lattice-sim/requirements.txt),
[`qubit_state_discrimination/requirements.txt`](qubit_state_discrimination/requirements.txt),
[`evaluation/motivation/MECH/requirements.txt`](evaluation/motivation/MECH/requirements.txt),
[`branch_instruction/qubic-software/pyproject.toml`](branch_instruction/qubic-software/pyproject.toml).

## Reproducing the QEC results (surface code, § 3.3 and § 8.5)

The surface-code logical-error-rate simulations (Fig. 3, the Google
Sycamore motivation figures in § 3.3, and Fig. 13, the 4-panel
IBM-Heron/futuristic/patches/threshold evaluation in § 8.5) are produced by
**`lattice-sim`**, vendored here at [`lattice-sim/`](lattice-sim/).

`lattice-sim` is an independent QEC simulator built for:

> S. Maurya and S. Tannu, "Synchronization for Fault-Tolerant Quantum
> Computers," ISCA 2025. https://doi.org/10.1145/3695053.3730991

It also has its own dedicated artifact on Zenodo:
https://zenodo.org/records/15092177 — note that Zenodo record is the
*original* upstream artifact; `lattice-sim/` here additionally carries the
MCM-latency scripts, presets, and pre-run results (`evaluate_mcm_error.py`,
`evaluate_mcm_latency.py`, `run_tradeoff_final.py`, `evaluate_patches.py`,
etc.) written specifically to produce this paper's Fig. 3 and Fig. 13, which
are not part of the Zenodo snapshot.

`lattice-sim` was previously reached only through a git submodule on
[ECCentric](https://github.com/TUM-DSE/eccentric)'s `mcm-latency-eccentric`
branch (as its `synchronization-artifact/` subfolder), since the two tools
happen to share the same Stim/pymatching stack. It has zero dependency on
the rest of ECCentric, so it's vendored directly at `lattice-sim/` instead
(full commit history preserved via `git subtree`) — there is no more
`eccentric/` submodule in this repo.

Layout:
- `lattice-sim/` — the simulator itself (`sim/`, `evaluate_*.py`, `run_*.py`, Dockerfile, requirements.txt)
- `lattice-sim/experiment_results/` — the CSVs consumed by the plots below
- `lattice-sim/plotting/` — the plotting notebook/script that renders the CSVs into the paper figures
- `lattice-sim/data/` — the resulting PDFs

See `lattice-sim/README.md` and `lattice-sim/Dockerfile` for environment
setup (Stim + pymatching).

### Fig. 3 — MCM error rate / duration motivation (§ 3.3)

Data (Google Sycamore preset, d=7,9,11) is generated by:
- `lattice-sim/evaluate_mcm_error.py --preset google` → `mcm_error_ler_google.csv`
- `lattice-sim/evaluate_mcm_latency.py --preset google` → `mcm_latency_ler_google.csv`

Both scripts also support `--preset ibm` and `--preset ibm_futuristic`, each
with an explicit, sourced T1/T2/gate-error/idle-multiplier block documented
in `evaluate_mcm_error.py`'s module docstring (`google` defaults if
`--preset` is omitted, since that's what Fig. 3 needs).

Pre-generated CSVs are committed under `lattice-sim/experiment_results/`, so
the plotting step below works without re-running the simulation. Plotted via
`plot_logical_error_rate_two_panel(...)` in
`lattice-sim/plotting/mcm_plot.ipynb` (cells 12-14), which saves to
`lattice-sim/data/mcm_motivation.pdf`.

Note: the scripts write their CSV to their own working directory
(`lattice-sim/`), *not* `lattice-sim/experiment_results/` — that's a
separate copy the plotting notebook reads from. If you re-run a script, copy
its output CSV into `lattice-sim/experiment_results/` before re-plotting
(this matches the original artifact's own run-then-copy convention).

### Fig. 13 — 4-panel QEC evaluation (§ 8.5)

Data is generated by, all in `lattice-sim/`:
- `run_tradeoff_final.py` / `run_herqules_both.py` / `run_herqules_futuristic.py`
  → `mcm_tradeoff_{mcm,herqules}_ibm.csv`, `mcm_tradeoff_{mcm,herqules}_futuristic_2.csv`
  (panels a/b: MCMit vs. HERQULES, current and futuristic noise)
- `evaluate_patches.py` → `mcm_patch_dist.csv` (panel c: QEC patches)
- `evaluate_mcm_error_latency.py` → `mcm_error_latency_ibm.csv` (panel d: QEC threshold)

Rendered via `plot_four_panel(...)` in `lattice-sim/plotting/_render_four_panel.py`
(also invoked from `lattice-sim/plotting/mcm_plot.ipynb`), which saves to
`lattice-sim/data/mcm_qec_evaluation.pdf`.
